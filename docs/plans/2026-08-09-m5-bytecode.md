## 一、可行性实测结论（推翻「只能自研」）

2026-08-09 实测（JDK 17 + jawa 2.2.0）：

1. `pip install jawa` 成功（2.2.0，MIT 协议）
2. 用 `javac` 编译含硬编码字符串的 `Test.java` → jawa 解析出 `String` 常量条目
3. jawa 修改 `String.value` → save → `java` 运行修改后 class：**输出变成中文，技术串原样保留**

| 来源 | 协议 | 用法 |
|---|---|---|
| **Jawa**（Python 库） | MIT | 直接使用，解析/修改/保存 class |
| **MCC-i18n** | MIT | 算法参考：遍历常量池字符串匹配替换 |
| **xtmc** | 无 LICENSE | 仅参考思路（LDC 提取、技术串过滤），不抄代码 |
| JVM 规范（JVMS） | 公开标准 | 格式公开，解析合法性无忧 |

**安全策略**：修改只发生在「复制到 work 目录的 jar 副本」上，原始 mod jar 只读不动（铁律延续）；每个 class 修改后**重读校验**，解析/校验失败则跳过该 class 并记录；jar 级 `.bak` 快照备份。

## 二、技术方案

### 2.1 核心 API（jawa）

```python
from jawa.classloader import ClassLoader
from jawa.constants import String

klass = ClassLoader('.')['类名']      # 目录根 + 类名
for c in klass.constants:             # 常量池条目
    if isinstance(c, String):
        value = c.string.value        # 字符串字面量值
c.string.value = "新值"               # 修改（改写所引用的 Utf8）
with open(out, 'wb') as f:
    klass.save(f)                     # 全量重建保存
```

注意：`ClassLoader` 接收**目录根**（jar 需先解压）；String 条目 = 代码里的字符串字面量（含 `System.out.println("...")` 这种硬编码）。

### 2.2 技术串过滤（参考 xtmc/MCC-i18n 思路）

在复用 `common.should_translate` 基础上，对字节码场景追加：

- 纯大写缩写（`OK`、`FPS`）跳过
- 含 `.` 且全为合法 Java 标识符段（类路径/包名）跳过
- 含 `/` 的路径跳过
- 形如 `modid:xxx`（含冒号无空格）跳过
- 长度 < 2 或 > 100 跳过
- 含 `%s %d %f` 占位符的**保留**（翻译时须保留占位符）

### 2.3 扫描与替换

- **扫描** `scan_hardcoded_strings(jar: Path) -> list[str]`：解压 jar → 遍历 `*.class` → jawa 提取 String 常量 → 去重 → 过滤 → 返回可翻译字符串
- **替换** `replace_hardcoded_strings(jar: Path, mapping: dict[str, str]) -> int`：解压 jar → 逐 class 修改 → 每 class 改后重读校验（能解析 + String 数量一致）→ 失败记入 failed 并跳过该 class → 重新打包 jar → 返回替换成功条数
- **校验**：class 修改后立即用 jawa 重新加载，抛异常或计数不一致 → 该 class 还原原字节
